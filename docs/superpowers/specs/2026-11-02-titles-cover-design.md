# 세로 제목과 AI 대표 사진

작성 2026-11-02 · 브랜치 `titles-cover`

## 목표

1. 사이트 이름, 방 이름, 목록, 사진 라벨이 모두 12~14px이라 글자에 특색이 없다. 사이트 이름과 방 이름을 **세로쓰기로 크게** 세운다.
2. 맨 위 대표 사진을 **메인처럼 크게** 걸고, 그 사진은 **게시할 때마다 AI가 다시 고른다**.

## 고른 과정

시안은 지금 사진과 지금 문구로 만든 비교 페이지에서 골랐다(시안 파일은 git에 올리지 않는다).

- 제목: A 벽글(방 이름을 가로로 크게), B 표제(사이트 이름을 폭 가득), C 세로 제목 중 **C**.
- C의 폰: 처음 시안(폰에서는 가로로 눕힘)은 세로쓰기가 사라져 어색했다. 보완 1(첫 줄 사진 옆에 세움)과 보완 2(넓은 화면처럼 좁은 기둥으로 따라옴) 중 **보완 2**.
- 대표 사진 크기: 열 가득과 화면 가득 중 **열 가득**. 자르지 않으면 가로로 긴 사진은 폰에서 지금(높이 164px)보다 커지지 않으므로, 대표 사진만 화면 틀에 맞춰 자른다.
- 열 가득만으로는 넓은 화면 첫 화면의 가장 큰 글자가 24px짜리 이름뿐이었다. "Nocturne"을 대표 사진의 세로 제목으로 세우는 안과 왼쪽 열 맨 위에 세우는 안 중 **왼쪽 열 맨 위**. 낮은 창에서 왼쪽 열 아래 작은 글씨가 잘리던 문제는 크기가 창 높이도 따라가게 해서 풀었다.
- AI가 고르는 때: 게시할 때마다 다시 고름, 정해진 주기, 새 사진만 판단, 관리 페이지 버튼 중 **게시할 때마다 다시 고름**. 사람이 관리 페이지에서 고른 대표는 AI가 바꾸지 않는다.

## 하지 않는 것

- 관리 페이지의 모양, 크게 보기, 사진 라벨·목록·작은 글씨의 크기, 색.
- PC 도우미(12B)나 e4b가 대표를 고르는 일. 여러 장을 견주는 일은 작은 모델이 약하다.
- 대표 사진의 중심점을 사람이 정하는 화면. 사람이 고른 대표도 중심점은 AI가 정한다.
- 사진이 아주 많을 때 후보를 줄이는 규칙. 한 번에 100장까지만 보낸다는 상한만 둔다.

## 1. 화면

### 글꼴

- Noto Serif KR 400에 300을 더한다. 300은 "Nocturne"과 방 이름(한국어·영어)에만 쓴다.
- 300은 두 번째 Google Fonts 스타일시트로 받는다: `css2?family=Noto+Serif+KR:wght@300&text=<글자>&display=swap` (`crossorigin`). `<글자>`는 빌드가 사이트 이름과 모든 방의 `name`, `name_en`에서 모은 글자(겹치지 않게, 코드 순서)를 URL 인코딩한 것이다. 두 페이지가 같은 주소를 쓴다. 서비스 워커는 글꼴을 출처로 가려 담으므로 이 파일도 오프라인용으로 담긴다.
- 크기: 본문 14px, 라벨 13px, 작은 글씨 12px은 그대로다. 큰 글자는 둘뿐이다.
  - 넓은 화면의 사이트 이름: `max(56px, min(7.6vw, 124px, (100svh - 22rem) / 4.6))`. 1920×1080에서 124px, 1440×900에서 109px, 1280×720에서 80px, 960×600에서 56px. 창 높이를 따라가므로 왼쪽 열이 넘치지 않는다.
  - 방 이름: 넓은 화면 `clamp(40px, 4vw, 60px)`, 폰 28px.
  - 폰 위 줄의 사이트 이름은 14px에서 20px로.
- 이탤릭, 자간, 대문자 변환, 굵게는 그대로 쓰지 않는다.

### 넓은 화면 (960px 이상)

- 왼쪽 열: 맨 위에 "Nocturne"을 세로쓰기(`writing-mode: vertical-rl`)로 세운다. 36px 띄우고 방 목록, 28px 띄우고 언어 링크, 맨 아래 작은 글씨 세 줄. 왼쪽 열은 지금처럼 따라온다.
- 방: `[이름 기둥 | 사진]` 두 칸(`grid-template-columns: auto minmax(0, 1fr)`, 사이 `clamp(20px, 2.4vw, 36px)`). 방 머리는 세로쓰기로 방 이름, 14px 띄우고 점수·기간(12px, `--ink-dim`)이 그 아래로 이어진다. 방 머리는 `position: sticky; top: var(--lead)`로 방을 내려가는 동안 따라온다.
- 대표 사진: 오른쪽 열 폭에, 높이는 첫 화면 아래 끝까지(`100svh - 2 × 바깥 여백 - 라벨 한 줄 28px`).

### 폰 (960px 미만)

- 방: 넓은 화면과 같은 두 칸, 사이 10px, 방 이름 28px, 점수·기간과는 10px. 방 머리는 위 줄 아래 8px에 붙어 따라온다.
- 이름 기둥(약 38px)만큼 좁아진 사진 줄에서도 두 장씩 서도록, 정렬 배치의 목표 줄 높이를 줄 폭 400px 미만에서 180 대신 150으로 한다.
- 대표 사진: 좌우 여백 없이 화면 폭 가득, 4:5 틀. 라벨은 바깥 여백 안쪽에 둔다.

### 공통

- 방 머리 마크업: `<header class="room-head"><h2>강</h2><p class="room-meta"><span class="room-count">7점</span><span class="room-span">2026.09 – 2026.10</span></p></header>`. 기간이 없으면 `room-span`이 없다.
- 세로쓰기에서 점수의 숫자는 바로 세운다(`text-combine-upright: digits 2`). 기간과 영어 방 이름은 책등처럼 옆으로 눕는다.
- 방 사이는 `clamp(96px, 11vw, 160px)`.
- 대표 사진은 `object-fit: cover`로 틀에 맞추고 `object-position: var(--fx) var(--fy)`로 AI가 정한 중심을 남긴다. 빌드가 `cover_focus`를 `--fx`, `--fy`(퍼센트)로 넣고, 없으면 50% 50%다. 누르면 크게 보기에서 원본 비율 그대로 보인다. 방의 사진은 지금처럼 자르지 않는다.

## 2. AI가 대표 고르기

### photos.json

| 키 | 값 | 뜻 |
|---|---|---|
| `cover` | `"0306"` | 대표 사진 (지금 그대로) |
| `cover_focus` | `[0.42,0.5]` | 잘릴 때 남길 곳. 가로, 세로 0~1 (왼쪽 위가 0,0). 두 자리 소수, 0이나 1은 정수. 없으면 가운데 |
| `cover_pick` | `{"by":"ai","model":"claude-opus-5-5","seen":"3fa9c2d1"}` | AI가 고름. `seen`은 그때 전시 중이던 사진들의 지문 |
| | `{"by":"person"}` | 사람이 관리 페이지에서 고름. AI는 사진을 바꾸지 않는다 |
| | 없음 | AI가 고를 차례 (이 기능 전의 대표, 또는 관리 페이지의 "AI에게 맡기기") |

- 위치는 `site` 다음 `cover`, `cover_focus`, `cover_pick` 순이고, 각각 한 줄이다(공백 없는 구분자). `photolib.dumps_data`와 관리 페이지의 `serialize`가 맨 위 키를 이 순서로 놓고 글자까지 같게 쓴다.
- 지문: 전시 중인 사진 이름을 정렬해 줄바꿈으로 이은 글의 sha256 앞 8자리. 사진이 들어오거나 빠지면 바뀐다.

### 언제

`draft.yml`의 Claude 단계 바로 뒤에 `대표 사진 고르기` 단계(`python scripts/cover.py`)를 둔다. Ollama를 내려받기 전이라, Anthropic 키가 Ollama가 도는 동안의 단계에 닿지 않는다는 규칙이 그대로 지켜진다. 이 단계는 실패해도 실행을 멈추지 않는다(`continue-on-error`).

`scripts/cover.py`가 지금 `photos.json`(GitHub API)을 보고 할 일을 정한다.

- 전시 중인 사진이 없으면 아무것도 하지 않는다.
- `cover_pick.by`가 `person`: 대표가 전시 중이고 `cover_focus`가 없으면 그 사진 한 장으로 **중심점만** 정한다. 아니면 아무것도.
- 그 밖: `cover_pick`이 없거나, 대표가 전시 중이 아니거나, `seen`이 지금 지문과 다르면 **고른다**. 아니면 아무것도.

그래서 Claude가 게시한 사진은 같은 실행에서, e4b·PC 도우미가 게시한 사진과 지운 사진은 다음 실행(30분마다 도는 `schedule`)에서 반영된다. 판단할 일이 없는 실행은 `photos.json`을 한 번 읽고 끝난다.

### 보내는 것

- 전시 중인 사진마다 "사진 `<file>`: `<제목>` (방: `<방 이름>`)" 한 줄과, 썸네일(`photos/thumb`, 메타데이터를 지운 사본)을 긴 변 512px로 줄인 JPEG. 페이지 순서. 100장이 넘으면 지금 대표와 앞에서부터 99장.
- 지시문(한국어): 사이트 첫 화면 맨 위에 크게 걸 한 장을 고른다. 혼자서 전시 전체를 대표할 만큼 인상이 강해야 한다. 넓은 화면에서는 가로가 조금 긴 틀(약 7:5), 폰에서는 세로 4:5 틀로 잘리니 두 틀 모두에서 주제가 살아야 한다. 잘릴 때 꼭 남길 곳을 `focus_x`, `focus_y`로 준다. 지금 대표가 있으면 알려 주고, 다른 사진이 뚜렷이 낫지 않으면 그대로 고르라고 한다(게시할 때마다 이유 없이 흔들리지 않게).
- 중심점만 정할 때는 그 사진 한 장과 틀 설명만 보낸다.
- 답: JSON Schema `{"file": <전시 중인 이름 중 하나>, "focus_x": number, "focus_y": number}`. 초안과 같은 설정(`effort: low`, 거절 대비 대체 모델)이다. 중심점은 0~1로 자르고 두 자리로 반올림한다.

### 기록

- `photos.json`만 바꾸는 한 커밋. 고르기는 `대표 사진: <제목> (AI)`, 중심점만은 `대표 사진 중심: <제목> (AI)`.
- 커밋을 만들 때 다시 읽은 `photos.json`이 여전히 같은 판단일 때만 쓴다. 그 사이 사람이 대표를 정했거나 고른 사진이 빠졌으면 쓰지 않는다.
- 고르기의 결과는 `cover`, `cover_focus`, `cover_pick`(`by` ai, 답한 모델, 지문)이다. 같은 사진을 다시 골라도 지문과 중심점은 새로 적는다.
- `cover`나 `cover_focus`가 바뀌었을 때만 `GITHUB_OUTPUT`에 `changed=1`을 적고, `사이트 다시 만들기` 단계가 이것도 본다.

### 실패

- 키가 없으면 "Claude API 키가 없어서 대표 사진을 고르지 않아요"만 찍고 끝난다.
- Claude가 못 고르면(초안과 같은 오류 문구들, 거절은 "Claude가 대표 사진 고르기를 거절했어요") Actions 기록에 `대표 사진` 경고를 남기고 대표는 그대로 둔다. 키·크레딧·요청 과다·연결 같은 실패는 다음 실행이 다시 해 본다.
- 돈이 들고 다시 물어도 같을 실패(거절, 끊긴 답, 읽을 수 없는 답)는 `cover_pick`에 `"tried": <그때의 지문>`을 적는다(커밋 `대표 사진: Claude가 못 고름`, 나머지 키는 그대로). 지문이 같은 동안은 고르지도 중심을 정하지도 않는다. 사진이 바뀌거나, 관리 페이지에서 **AI에게 맡기기**를 누르면(`cover_pick`이 지워진다) 다시 한다. 30분마다 도는 실행이 같은 실패에 돈을 계속 쓰지 않게 하려는 것이다 (검토에서 고침).
- GitHub 오류나 예상 못 한 오류는 traceback을 남기고 실패로 끝난다. 실행은 이어진다.

### 비용

512px 사본 한 장은 1000px 썸네일의 약 4분의 1 토큰이다. 지금 23장이면 고르기 한 번에 초안 두세 장 값(어림 $0.05)이 들고, 사진이 바뀐 실행에서만 든다. 실제 값은 Console에서 확인해 CLAUDE.md에 적는다.

## 3. 관리 페이지

- 전시 중 탭의 대표 사진 배지는 "대표 사진"(진하게) 뒤에 "AI가 고름" 또는 "직접 고름"을 흐리게 붙인다.
- 다른 사진의 **대표로 지정**: `cover`를 그 사진으로, `cover_pick`을 `{"by":"person"}`으로, `cover_focus`는 지운다(다음 실행에서 AI가 그 사진의 중심점만 정한다). 커밋 `대표 사진 변경: <제목>`(지금 그대로).
- 사람이 고른 대표와 AI가 못 고른 대표(`tried`)의 행에는 **AI에게 맡기기**가 생긴다 (배지 "AI가 못 고름"). 누르면 `cover_pick`을 지운다(`cover`, `cover_focus`는 그대로). 커밋 `대표 사진: AI에게 맡김`. 다음 Draft 실행(늦어도 30분 뒤)에서 AI가 고른다. 관리 페이지의 토큰은 Actions를 읽기만 하므로 바로 돌리지 않는다.
- 대표 사진은 지금처럼 지울 수 없다.

## 4. 시험

- Python
  - `photolib`: 맨 위 키 순서와 한 줄 쓰기, 정규 형식 고정 파일, 지문.
  - `cover`: 할 일 판단(세 갈래), 512px 사본(메타데이터 없음), 고르기·중심점 커밋, 그 사이 사람이 정한 경우, 실패 처리와 경고, `changed` 출력, 키 없음.
  - `curator.claude_pick_cover`: 요청 모양(사진 순서와 줄, 스키마의 이름 목록, 지금 대표 문구), 답 읽기, 중심점 자르기, 거절·끊김·읽을 수 없는 답·API 오류.
  - `build`: 방 머리 마크업, 대표의 `--fx`·`--fy`, 두 글꼴 주소, 세로쓰기·따라오기·대표 틀 CSS, 목표 줄 높이.
  - `draft.yml`: 단계 순서(Claude → 대표 → 남은 사진 찾기 → Ollama), 키는 Claude와 대표 단계에만, 사이트 다시 만들기 조건.
- JS: `gallery`(대표 지정이 `person`을 적고 중심점을 지움, AI에게 맡기기, Python과 같은 글자), `exhibit`(배지, AI에게 맡기기 버튼).
- 눈으로: 넓은 화면 1920×1080·1440×900·1280×720·960×600, 폰 390×844, 한국어·영어.
